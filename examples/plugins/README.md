# plugins (the effect gallery)

One live HTML form inside `<canvas content="drawable">`, and every effect plugin of this repository applied to it. The canvas is the first thing on the page, on a phone as on a desktop: a bar with the title and a frame readout, a strip of chips (one per effect, plus "Effect off"), then the stage. The form stays live under every effect: click a field and type.

- **Picking an effect** applies it to the form with its own controls (rendered as HTML inside the form by the plugin's `mountUI`). A plugin with an action `demo` plays it once, a short showcase of what it does (not when the user prefers reduced motion; any input takes over). `?effect=<name>` selects an effect on load (`?effect=off` none), `&demo=0` without the showcase.
- **The panel** beside the stage on wide screens, under it elsewhere, describes the selected plugin from its manifest entry: title, version, description, its actions as buttons (`handle.trigger`, with the state each resolves), what it does under reduced motion (`meta.reducedMotion`), the options the page passes (`meta.defaults`) and a link to its source. "About this page" says what the readout counts, the display rate the page measured and whether `prefers-reduced-motion: reduce` is in effect.
- **The readout** (top right) counts the `effectframe` events of the last second: effect frames per second, the interval between frames (median / 95th percentile, ms), the frame cap and the polyfill's mode. At rest it reads 0, unless the plugin is continuous by design (`meta.continuous`); it stops counting itself when no frame arrives.
- **The frame cap slider** (`canvas.frameCap`, inside the form) defaults to the display's rate, measured from 90 animation frames while the page starts (the 20th percentile of their intervals, which a busy frame cannot shorten); the page reports ready only after that, so the slider never changes the drawn form later. At its top the canvas is uncapped (`frameCap` 0, exactly the display rate).
- **The line under the title** is a short hint for the selected effect, for a finger on a touch screen and for a mouse elsewhere ("Move over the card to tilt it"); on a touch screen a plugin's `meta.touch` wins ("Drag the glass with a finger; tap through it to use the form."). Nothing on the page claims a touch: a drag on the stage scrolls the page unless it starts on a plugin's own handle, and the form fits the stage without an inner scroll.

Run: `npm run build && npm run demo`, then open `http://127.0.0.1:8765/examples/plugins/` in a browser with WebGPU.

How it works:
- The list comes from `dist/plugins/manifest.json`, which the build writes from every `plugins/<name>/` folder ([plugins/README.md](../../plugins/README.md)). A new plugin appears here without any change to this page.
- The page loads the core and the effects bundle; a plugin bundle (`dist/plugins/<name>.iife.min.js`) is loaded when it is first selected. Switching removes the previous plugin from the host (which also removes its controls) and adds the new one with the `defaults` of its manifest entry.
- Without WebGPU (or when `createHost` rejects) the page says so above the canvas, disables the effects and draws the same form through the plain 2D `drawElementImage` path, decided BEFORE any `getContext` call.

The effects host, the plugins and the frame cap are extensions of this library, not part of the HTML-in-Canvas proposal; browsers' native implementations do not provide them; the page runs them over the polyfill and over a browser's own implementation alike ([docs/guides/EFFECTS-PLUGINS.md](../../docs/guides/EFFECTS-PLUGINS.md#extensions-not-the-standard)).

Checked in headless Chrome:
- `npm run test:examples`: no console or page error, the canvas is not blank, every plugin of the manifest is listed, selecting it mounts its controls, changes the presented pixels and fills the panel (title, version, description, reduced-motion behaviour), "Effect off" removes them, typing reaches the live field, and the slider changes `canvas.frameCap`. A second run hides `navigator.gpu` and checks the message, the disabled effects and typing on the 2D path.
- `npm run test:gallery` (`scripts/check-gallery.mjs`): at 390 x 844 and 1194 x 748 with touch emulation, for every plugin and the template plugin: the stage entirely in the first viewport, the form without an inner scroll, the demo played on selection (and not under reduced motion), 0 effect frames over 2 s once the plugin settled (unless `meta.continuous`), a touch drag on the stage that scrolls the page, and the frame cap at the display rate; each check with a positive control that must turn it red.
- `npm run test:plugins`: the end-to-end test of each plugin drives this page with trusted input: clicks through the effect, its triggers, the frame cap and reduced motion.
