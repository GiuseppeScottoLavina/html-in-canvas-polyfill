# Bundles: what to load

`npm run build` (`scripts/build.mjs`, esbuild as a devDependency, zero runtime dependencies) writes five classic IIFE bundles (each as a readable `.js` and a `.min.js`), the same split as ES modules under `dist/esm/`, one classic and one ES module bundle per example plugin under `dist/plugins/` (with `manifest.json`), and `dist/sizes.json`. The size table below is generated by that build (bytes; gzip is level 9). `npm run check:bundle` (`scripts/check-bundle.mjs`, gate G-bundle) rebuilds, measures and loads every file in a headless Chrome.

> **Extensions are not the standard.** The FPS cap (`framecap`, `canvas.frameCap`) and the effects host with its plugin interface (`HTMLInCanvasEffects`) are extensions of this library, not part of the HTML-in-Canvas proposal. Browsers' native implementations do not and will not provide them. They work only while this polyfill provides the API (mode `polyfill`); on top of a native implementation they are not supported ([what was observed](guides/EFFECTS-PLUGINS.md#extensions-not-the-standard)). The plugins are not part of the polyfill either: they are examples in [`plugins/`](../plugins/), each built into its own bundle.

## Which file for which use case

| use case | load, in this order | what you get |
|---|---|---|
| 2D only (`<canvas content="drawable">`, `drawElementImage`, `paint`, the FPS cap extension) | `dist/hic-live-polyfill.iife.min.js` | `window.HicLivePolyfill`, installed on load |
| + Firefox 155+ / Safari 27+ (their form controls, classic scrollbars and shadows are drawn by the polyfill) | `hic-live-polyfill.iife.min.js` and `hic-live-engines.iife.min.js`, in any order | the Gecko / WebKit painters (not needed on Chromium; without them those engines keep the image look and the capture reports it once) |
| + WebGL / WebGPU texture upload of an element (`texElementSubImage2D`, `texElementImage2D`, `drawElementImageToTexture`, `copyElementImageToTexture`) | `hic-live-polyfill.iife.min.js` and `hic-live-gpu.iife.min.js`, in any order | the element-texture methods (without the bundle they exist and throw a NotSupportedError naming it) |
| 2D + effects (the WebGPU post-process host, plugin ABI, input interposer; an extension) | `hic-live-polyfill.iife.min.js`, then `hic-live-effects.iife.min.js` | + `window.HTMLInCanvasEffects` |
| + an example plugin, e.g. water | the two above and `plugins/water.iife.min.js` (any order) | + `window.HicLivePlugins.water` = `{meta, plugin, ...}` (WGSL inlined, no fetch) |
| Chrome 154-155 behind `--enable-blink-features=CanvasDrawElement` (the earlier `layoutsubtree` draft) or a native build missing a name the bridge can build | `hic-live-native-bridge.iife.min.js` BEFORE `hic-live-polyfill.iife.min.js` | mode `native-bridged` instead of the native build used as found |
| Chrome 157+ (complete native), Firefox 155+, Safari 27+ | Chrome: nothing extra; Firefox / Safari: `hic-live-engines.iife.min.js` with the core (row above) | complete native: mode `native` (the core does no snapshotting; the extensions are not supported); Firefox 155+ and Safari 27+: mode `polyfill`; older Firefox/Safari and mobile: refused loudly (one `console.warn`, `window.__HIC__.error`) |
| a bundler (Vite, webpack, rollup...) | `import { install } from '@giuseppe-scotto-lavina/html-in-canvas-polyfill'`, optionally `@giuseppe-scotto-lavina/html-in-canvas-polyfill/effects`, `.../plugins/water`, `.../native-bridge` | tree-shakeable ESM with shared chunks; each plugin is one self-contained module |

All scripts are classic `<script src>` tags (no `type=module`, no `import`), make no network request when they load, and the minified twins are drop-in replacements for the readable files (the gates and the mutants run the readable ones, G-bundle loads both).

```html
<script src="hic-live-polyfill.iife.min.js"></script>          <!-- installs synchronously; add data-hic-manual to call install() yourself -->
<script src="hic-live-effects.iife.min.js"></script>           <!-- optional: defines window.HTMLInCanvasEffects -->
<script src="plugins/water.iife.min.js"></script>              <!-- optional: window.HicLivePlugins.water -->
<script>
  const host = await HTMLInCanvasEffects.createHost(canvas, formElement, { interposer: true });
  await host.addPlugin(HicLivePlugins.water.plugin, { intensity: 0.28 });
</script>
```

## The files

| file | global it defines | needs |
|---|---|---|
| `hic-live-polyfill.iife(.min).js` | `HicLivePolyfill`, `__HIC__` | nothing |
| `hic-live-effects.iife(.min).js` | `HTMLInCanvasEffects` | the core, installed (looked up at every call, so the order of the two scripts only matters for `createHost`) |
| `plugins/<name>.iife(.min).js` | `HicLivePlugins.<name>` (all exports of `plugins/<name>/index.js`, frozen) | nothing to load; `HTMLInCanvasEffects` (the effects bundle) to use it |
| `hic-live-native-bridge.iife(.min).js` | registers on `Symbol.for('hic.native-bridge')` | loaded BEFORE the core installs |
| `hic-live-engines.iife(.min).js` | registers on `Symbol.for('hic.engine-skins')` | nothing; any order with the core (looked up at capture time) |
| `hic-live-gpu.iife(.min).js` | registers on `Symbol.for('hic.gpu-patches')` | nothing; before the core (install uses it) or after it (it replaces the stubs of the installed core) |
| `esm/index.js` (+ chunks) | exports `install`, `getInstalled`, `HicUnsupportedError`, `FEATURES`, `featureById`, `EVENTS`, `EXT`, `VERSION`; not minified (the consumer's bundler does it); carries the engines and GPU code (bundler users get every engine and the texture methods) | nothing |
| `esm/effects.js` | exports `installEffects(win)`, `createLateEffects`, `installEffectsGlobal`, `definePlugin`; no side effect | the core, installed |
| `plugins/<name>.esm.js` | the exports of `plugins/<name>/index.js` (`meta`, `plugin`, ...), WGSL inlined; no import | `effects.js` to use it |
| `plugins/manifest.json` | name, title, description, version, defaults and file names of every plugin (read by `examples/plugins/`) | |
| `esm/native-bridge.js` | registers the bridge when imported (listed in `sideEffects`) | import it before `install()` runs |

Size target: the design target for the minified core was 150 KB (gate G-bundle), and **the core in the table above is over it**. The bytes are spread across the whole pipeline (by module group, measured once: `api` about 26 %, `snapshot/capture` 24 %, `live` 20 %, `snapshot/store` 12 %, observers and scheduler 11 %); minifier settings cannot close the gap (mangling every long property name, which is not safe, would still leave about 183 KB), and the code that only some pages need (effects, the plugins, the native bridge, the Gecko / WebKit painters, the WebGL / WebGPU element textures) is already in separate bundles. `npm run check:bundle` therefore prints the target as KNOWN RED and fails on any growth above a recorded ceiling (`scripts/check-bundle.mjs`), which is raised only deliberately, with a measured reason.

### What the minified core is allowed to differ in

`HicLivePolyfill.FEATURES` in the classic core carries `{id, status}` per feature only (the `summary` / `reason` prose is about 15 KB minified and nothing at runtime reads it; the store reads `status`). `docs/SUPPORT-MATRIX.md` has the prose and the ESM build keeps the full table. The build fails if a row of `src/contracts/features.js` does not have the expected one-line shape, and G-bundle compares the ids and statuses of the minified table with the source table.

## Load order and the seam between core and effects

- **Core first.** `install()` is SYNCHRONOUS by contract (API-CONTRACT section 2): it patches the prototypes during script evaluation, before app scripts read the API.
- **Effects second (or any time before `createHost`).** The core never imports effects code. It publishes `{env, store, scheduler, geometry, tracker}` on the `HicInstalled` under `Symbol.for('hic.effects-seam')` (`createEffectsSeam` in `src/api/compose.js`); `HTMLInCanvasEffects` (`src/effects/index.js`, `createLateEffects`) looks the installed core up on every call. Before an install, after `uninstall()`, or without the core, `createHost` rejects with `InvalidStateError` ("needs the installed polyfill"); after a reinstall it works again. `uninstall()` destroys every host through the seam's `cleanups`.
- **Plugins in any order.** A plugin bundle has no dependency: it only registers its module under `window.HicLivePlugins`. `host.addPlugin` validates the definition (`definePlugin`), so a plugin needs the effects bundle only when it is used. The build checks every plugin folder against the contract of `plugins/README.md` before it bundles it.
- **Bridge before the core.** `install()` decides the mode synchronously. For a legacy or nearly complete native implementation it needs the bridge already registered.

## The Chrome core, the engines bundle and the GPU bundle

The classic core is what a Chromium page loads, so code that only another engine or an optional API needs is outside it, in explicit opt-in bundles that make no request by themselves (the contract above: every bundle is a plain `<script src>` the page lists):
- `hic-live-engines`: the Gecko / WebKit form-control skins ported from the engines' painters (`native-controls.js`, `webkit-skins.js`, `gecko-skins.js`), the WebKit classic scrollbars (`webkit-bars.js`), the WebKit shadow rewrite (`webkit-shadow.js`) and the style rules for the controls it paints (added to every clone's base sheet while it is registered). Chromium draws native controls inside SVG images itself, so the core never needs them there. The capture looks the painter up through `snapshot/capture/engine-skins.js`; on Firefox / Safari without it, it reports `engine-gecko` / `engine-webkit` once.
- `hic-live-gpu`: WebGL / WebGPU element textures (`api/texture-patch.js`, `texture-math.js`), registered for `api/gpu-seam.js`. Without it the four methods still exist (feature detection unchanged) and throw a NotSupportedError naming the bundle; loaded after the core it replaces the stubs of the installed core.
- Not moved: the OffscreenCanvas transfer patch (the 2D patch depends on it) and the worker / fullscreen guards (they are the loud failure for unsupported uses: without them a managed canvas sent to a worker would break silently).
- The ESM package entry imports both, so bundler users keep one import for everything.

## What had to stay in the core, and the native-bridge decision

Core = the 2D polyfill: native detection (`native-detect.js`: it decides between "nothing to do", "polyfill" and "refuse", so it cannot be lazy), options, registry, patches (canvas, 2D, offscreen, texture variants, guards), live layer, selector bridge, capture (clone, CSS, scroll emulation, caret), snapshot store and pump, scheduler, observers, reporter, and the effects SEAM (a 14-line module).

Moved out: the effect host, plugin ABI, GPU presenter, source providers, input mapper, interposer and frame sources (the effects bundle), the plugins (outside `src/` altogether, in `plugins/`), and the native bridge (`native-bridge.js` + `native-geometry.js` with its glue). Their sizes are in the generated table above.

Native bridge, with the evidence for "separate script, not lazy":
- It is only needed for a LEGACY native (Chrome 154 and 155 behind a flag) or a native missing a name it can build. Chrome Canary 157 (a complete native) needs nothing of it, and 154-156 without the flag has no native, so the polyfill path runs. No gate runs the bridged mode end to end; its unit tests (`test/unit/api-core/native-bridge.browser.test.mjs`, `install.browser.test.mjs`) load it through the same registration as a page would.
- It cannot be fetched lazily: `install()` is synchronous (a fetch would make it asynchronous), the IIFE auto-installs during evaluation, and G-bundle requires no network request at load. So it is a second script that the page includes on purpose. When it is missing the core never throws: it uses the native build as found (mode `native`), records a `native-step-aside` entry in `report().deviations` that names the built files `dist/hic-live-native-bridge.iife.min.js` (or the readable `hic-live-native-bridge.iife.js`), and for the earlier `layoutsubtree` draft prints one `console.warn`, because `content="drawable"` canvases are not drawable there without the bridge.
- A "native-complete-only" shell (load a tiny script, fetch the core only when the browser has no native) would be the lazy alternative. It is not built: it would make the first install asynchronous, which API-CONTRACT section 2 forbids.

## Behaviour changes against the single-bundle layout

1. `window.HTMLInCanvasEffects` exists only when `hic-live-effects.iife.js` (or `installEffects()` of the ESM entry) ran. Before, the core defined it on install and removed it on uninstall; now it stays defined after `uninstall()` and its `createHost` rejects until the next install.
2. A legacy or nearly complete native is refused unless the bridge bundle is loaded (above).
3. The classic core's `FEATURES` has no `summary` / `reason` (above).
4. A built plugin never fetches its `.wgsl` files (they are inlined at build time). Served as source (`plugins/<name>/index.js`) it fetches each one once through its `wgsl.js`, the only module the build swaps.
5. `package.json` `exports`: `.` is `dist/esm/index.js`; `./effects`, `./native-bridge` are the ESM entries; `./plugins/<name>` is a plugin's ES module (types in `dist/types/plugins/<name>/`), `./plugins/<name>/iife` and `./plugins/<name>/iife/min` its classic files, `./plugins/manifest.json` the list; `./iife`, `./iife/effects`, `./iife/native-bridge`, `./iife/engines`, `./iife/gpu` (each with a `/min` twin) are the classic files. The sources under `src/` ship for reference and source maps but are not an entry point: they are internal and change without notice. The plugin subpaths are patterns, so a new plugin needs no change to `package.json`.

## Checks

- `npm run build`: the artifacts above plus `dist/sizes.json`; it fails when a plugin folder breaks the contract of `plugins/README.md`.
- `npm run check:bundle` (`npm test` and CI run it with `--allow-size`): sizes against the size budget, the measured size plus a small margin (min files; core 265.5 KB, effects 27.25 KB, bridge 11.5 KB, engines 38.5 KB, GPU 10.75 KB; gzip level 9: core 92.35 KB, effects 10.75 KB, bridge 4.5 KB, engines 15 KB, GPU 4.25 KB; each plugin its measured size plus a small margin (`PLUGIN_LIMITS`: crt 14, disintegrate 26.5, glitch 13.5, holo-card 12.75, liquid-glass 12.25, page-curl 33.5, shatter 29, water 10.75 KB) and 16 KB for a plugin not listed there; 1 KB = 1000 bytes, as in the target) and the 150 KB target; each IIFE parses as a classic script and has no dynamic `import()`; in headless Chrome, for the readable and the minified files: core alone, core + effects (including `createHost` rejecting after `uninstall()`), core + effects + each plugin of `dist/plugins/manifest.json` (it registers, `definePlugin` accepts it, its shader modules receive inlined WGSL strings), bridge + core, each with ZERO requests beyond the declared scripts (server log and Resource Timing) and no page error; the ESM build as native modules. Its controls: a module is not a classic script, a dynamic import and an oversize bundle are seen, an undeclared script is an unexpected request, a missing global is reported.
- `npm run test:examples` (`scripts/check-examples.mjs`) loads the minified bundles from `dist/` in the six pages of `examples/` (the plugin gallery included) and in the two smoke pages of `test/examples-smoke/` (the ESM entry `dist/esm/index.js` and a plugin written against `hic-live-effects.iife.min.js`), in headless Chrome, with a control that breaks the `dist/` path.
- The browser gates (`test/gates/`) load the core, and the effects bundle and `dist/plugins/water.iife.js` for the effect gates, from `dist/` through `--bundle-file`, `--effects-file` and `--water-file`; the mutant suite mutates the core or the effects file (`bundle: 'effects'`) and runs the gates on it.
