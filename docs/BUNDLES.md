# Bundles: what to load

`npm run build` (`scripts/build.mjs`, esbuild as a devDependency, zero runtime dependencies) writes six classic IIFE bundles (each as a readable `.js` and a `.min.js`), the same split as ES modules under `dist/esm/`, and `dist/sizes.json`. The size table below is generated by that build (bytes; gzip is level 9). `npm run check:bundle` (`scripts/check-bundle.mjs`, gate G-bundle) rebuilds, measures and loads every file in a headless Chrome.

## Which file for which use case

| use case | load, in this order | what you get |
|---|---|---|
| 2D only (`<canvas content="drawable">`, `drawElementImage`, `paint`, FPS cap) | `dist/hic-live-polyfill.iife.min.js` | `window.HicLivePolyfill`, installed on load |
| + Firefox 155+ / Safari 27+ (their form controls, classic scrollbars and shadows are drawn by the polyfill) | `hic-live-polyfill.iife.min.js` and `hic-live-engines.iife.min.js`, in any order | the Gecko / WebKit painters (not needed on Chromium; without them those engines keep the image look and the capture reports it once) |
| + WebGL / WebGPU texture upload of an element (`texElementSubImage2D`, `texElementImage2D`, `drawElementImageToTexture`, `copyElementImageToTexture`) | `hic-live-polyfill.iife.min.js` and `hic-live-gpu.iife.min.js`, in any order | the element-texture methods (without the bundle they exist and throw a NotSupportedError naming it) |
| 2D + effects (WebGPU post-process host, plugin ABI, input interposer) | `hic-live-polyfill.iife.min.js`, then `hic-live-effects.iife.min.js` | + `window.HTMLInCanvasEffects` |
| + the water demo plugin | `hic-live-polyfill`, `hic-live-effects`, then `hic-live-effects-water.iife.min.js` | + `window.HicLiveEffectsWater.WaterEffectPlugin` (WGSL inlined, no fetch) |
| Chrome 154-156 behind `--enable-blink-features=CanvasDrawElement` (legacy or nearly complete native) | `hic-live-native-bridge.iife.min.js` BEFORE `hic-live-polyfill.iife.min.js` | mode `native-bridged` instead of a refusal |
| Chrome 157+ (complete native), Firefox 155+, Safari 27+ | Chrome: nothing extra; Firefox / Safari: `hic-live-engines.iife.min.js` with the core (row above) | complete native: mode `native` (the core does no snapshotting); Firefox 155+ and Safari 27+: mode `polyfill`; older Firefox/Safari and mobile: refused loudly (one `console.warn`, `window.__HIC__.error`) |
| a bundler (Vite, webpack, rollup...) | `import { install } from '@giuseppescottolavina/html-in-canvas-polyfill'`, optionally `@giuseppescottolavina/html-in-canvas-polyfill/effects`, `.../effects/water`, `.../native-bridge` | tree-shakeable ESM with shared chunks |

All scripts are classic `<script src>` tags (no `type=module`, no `import`), make no network request when they load, and the minified twins are drop-in replacements for the readable files (the gates and the mutants run the readable ones, G-bundle loads both).

```html
<script src="hic-live-polyfill.iife.min.js"></script>          <!-- installs synchronously; add data-hic-manual to call install() yourself -->
<script src="hic-live-effects.iife.min.js"></script>           <!-- optional: defines window.HTMLInCanvasEffects -->
<script src="hic-live-effects-water.iife.min.js"></script>     <!-- optional: window.HicLiveEffectsWater.WaterEffectPlugin -->
<script>
  const host = await HTMLInCanvasEffects.createHost(canvas, formElement, { interposer: true });
  await host.addPlugin(HicLiveEffectsWater.WaterEffectPlugin, { intensity: 0.28 });
</script>
```

## The files

| file | global it defines | needs |
|---|---|---|
| `hic-live-polyfill.iife(.min).js` | `HicLivePolyfill`, `__HIC__` | nothing |
| `hic-live-effects.iife(.min).js` | `HTMLInCanvasEffects` | the core, installed (looked up at every call, so the order of the two scripts only matters for `createHost`) |
| `hic-live-effects-water.iife(.min).js` | `HicLiveEffectsWater` | `hic-live-effects` (its `definePlugin` is reused, so the plugin ABI is not carried twice) |
| `hic-live-native-bridge.iife(.min).js` | registers on `Symbol.for('hic.native-bridge')` | loaded BEFORE the core installs |
| `hic-live-engines.iife(.min).js` | registers on `Symbol.for('hic.engine-skins')` | nothing; any order with the core (looked up at capture time) |
| `hic-live-gpu.iife(.min).js` | registers on `Symbol.for('hic.gpu-patches')` | nothing; before the core (install uses it) or after it (it replaces the stubs of the installed core) |
| `esm/index.js` (+ chunks) | exports `install`, `getInstalled`, `HicUnsupportedError`, `FEATURES`, `featureById`, `EVENTS`, `EXT`, `VERSION`; not minified (the consumer's bundler does it); carries the engines and GPU code (bundler users get every engine and the texture methods) | nothing |
| `esm/effects.js` | exports `installEffects(win)`, `createLateEffects`, `installEffectsGlobal`, `definePlugin`; no side effect | the core, installed |
| `esm/effects-water.js` | exports `WaterEffectPlugin`, `mapWaterPoint`, `RIPPLE_COUNT`, `GLOBALS_LENGTH`; WGSL inlined; shares the plugin ABI chunk with `effects.js` | `effects.js` |
| `esm/native-bridge.js` | registers the bridge when imported (listed in `sideEffects`) | import it before `install()` runs |

Size target: the design target for the minified core was 150 KB (gate G-bundle), and **the core in the table above is over it**. The bytes are spread across the whole pipeline (by module group, measured once: `api` about 26 %, `snapshot/capture` 24 %, `live` 20 %, `snapshot/store` 12 %, observers and scheduler 11 %); minifier settings cannot close the gap (mangling every long property name, which is not safe, would still leave about 183 KB), and the code that only some pages need (effects, the water plugin, the native bridge, the Gecko / WebKit painters, the WebGL / WebGPU element textures) is already in separate bundles. `npm run check:bundle` therefore prints the target as KNOWN RED and fails on any growth above a recorded ceiling (`scripts/check-bundle.mjs`), which is raised only deliberately, with a measured reason.

### What the minified core is allowed to differ in

`HicLivePolyfill.FEATURES` in the classic core carries `{id, status}` per feature only (the `summary` / `reason` prose is about 15 KB minified and nothing at runtime reads it; the store reads `status`). `docs/SUPPORT-MATRIX.md` has the prose and the ESM build keeps the full table. The build fails if a row of `src/contracts/features.js` does not have the expected one-line shape, and G-bundle compares the ids and statuses of the minified table with the source table.

## Load order and the seam between core and effects

- **Core first.** `install()` is SYNCHRONOUS by contract (API-CONTRACT section 2): it patches the prototypes during script evaluation, before app scripts read the API.
- **Effects second (or any time before `createHost`).** The core never imports effects code. It publishes `{env, store, scheduler, geometry, tracker}` on the `HicInstalled` under `Symbol.for('hic.effects-seam')` (`src/api/effects-seam.js`); `HTMLInCanvasEffects` (`src/effects/index.js`, `createLateEffects`) looks the installed core up on every call. Before an install, after `uninstall()`, or without the core, `createHost` rejects with `InvalidStateError` ("needs the installed polyfill"); after a reinstall it works again. `uninstall()` destroys every host through the seam's `cleanups`.
- **Water third.** The classic water bundle calls `HTMLInCanvasEffects.definePlugin` at load, so it throws a clear error when the effects bundle is missing. The ESM water entry imports the plugin ABI directly.
- **Bridge before the core.** `install()` decides the mode synchronously. For a legacy or nearly complete native implementation it needs the bridge already registered.

## The Chrome core, the engines bundle and the GPU bundle

The classic core is what a Chromium page loads, so code that only another engine or an optional API needs is outside it, in explicit opt-in bundles that make no request by themselves (the contract above: every bundle is a plain `<script src>` the page lists):
- `hic-live-engines`: the Gecko / WebKit form-control skins ported from the engines' painters (`native-controls.js`, `webkit-skins.js`, `gecko-skins.js`), the WebKit classic scrollbars (`webkit-bars.js`) and the WebKit shadow rewrite (`webkit-shadow.js`). Chromium draws native controls inside SVG images itself, so the core never needs them there. The capture looks the painter up through `snapshot/capture/engine-skins.js`; on Firefox / Safari without it, it reports `engine-gecko` / `engine-webkit` once.
- `hic-live-gpu`: WebGL / WebGPU element textures (`api/texture-patch.js`, `texture-math.js`), registered for `api/gpu-seam.js`. Without it the four methods still exist (feature detection unchanged) and throw a NotSupportedError naming the bundle; loaded after the core it replaces the stubs of the installed core.
- Not moved: the OffscreenCanvas transfer patch (the 2D patch depends on it) and the worker / fullscreen guards (they are the loud failure for unsupported uses: without them a managed canvas sent to a worker would break silently).
- The ESM package entry imports both, so bundler users keep one import for everything.

## What had to stay in the core, and the native-bridge decision

Core = the 2D polyfill: native detection (`native-detect.js`: it decides between "nothing to do", "polyfill" and "refuse", so it cannot be lazy), options, registry, patches (canvas, 2D, offscreen, texture variants, guards), live layer, selector bridge, capture (clone, CSS, scroll emulation, caret), snapshot store and pump, scheduler, observers, reporter, and the effects SEAM (a 14-line module).

Moved out: the effect host, plugin ABI, GPU presenter, source providers, input mapper, interposer and frame sources (the effects bundle), the water plugin, and the native bridge (`native-bridge.js` + `native-geometry.js` with its glue). Their sizes are in the generated table above.

Native bridge, with the evidence for "separate script, not lazy":
- It is only needed for a LEGACY native (Chrome 154-156 behind a flag) or a native missing additive names. Chrome 157+ with a complete native needs nothing of it, and 154-156 without the flag has no native, so the polyfill path runs. No gate runs the bridged mode end to end; its unit tests (`test/unit/api-core/native-bridge.browser.test.mjs`, `install.browser.test.mjs`) load it through the same registration as a page would.
- It cannot be fetched lazily: `install()` is synchronous (a fetch would make it asynchronous), the IIFE auto-installs during evaluation, and G-bundle requires no network request at load. So it is a second script that the page includes on purpose, and the core refuses loudly when it is missing: `HicUnsupportedError('partial-native')` from `install()` (one `console.warn` and `window.__HIC__.error` in the auto-install of the IIFE) whose hint names the built files `dist/hic-live-native-bridge.iife.min.js` (or the readable `hic-live-native-bridge.iife.js`). This is the one behaviour change for existing users of the flag; Chrome 157+ and the stable channel are not affected.
- A "native-complete-only" shell (load a tiny script, fetch the core only when the browser has no native) would be the lazy alternative. It is not built: it would make the first install asynchronous, which API-CONTRACT section 2 forbids.

## Behaviour changes against the single-bundle layout

1. `window.HTMLInCanvasEffects` exists only when `hic-live-effects.iife.js` (or `installEffects()` of the ESM entry) ran. Before, the core defined it on install and removed it on uninstall; now it stays defined after `uninstall()` and its `createHost` rejects until the next install.
2. A legacy or nearly complete native is refused unless the bridge bundle is loaded (above).
3. The classic core's `FEATURES` has no `summary` / `reason` (above).
4. The water plugin no longer fetches `water.wgsl` in a built bundle (the WGSL is inlined at build time). Served as source (`src/effects/water/water-plugin.js`) it still fetches it once, as before (`src/effects/water/shader-source.js` is the only module the build swaps).
5. `package.json` `exports`: `.` is `dist/esm/index.js`; `./effects`, `./effects/water`, `./native-bridge` are the ESM entries; `./iife`, `./iife/effects`, `./iife/effects-water`, `./iife/native-bridge` (each with a `/min` twin) are the classic files; `./src/*` exposes the sources.

## Checks

- `npm run build`: the six artifacts above plus `dist/sizes.json`.
- `npm run check:bundle` (`npm test` runs it with `--allow-size`): sizes against the ceilings (min files; core 207 KB, effects 27 KB, water 10.5 KB, bridge 11 KB; 1 KB = 1000 bytes, as in the target) and the 150 KB target; each IIFE parses as a classic script and has no dynamic `import()`; in headless Chrome, for the readable and the minified files: core alone, core + effects (including `createHost` rejecting after `uninstall()`), core + effects + water (the shader module receives an inlined WGSL string), bridge + core, each with ZERO requests beyond the declared scripts (server log and Resource Timing) and no page error; the ESM build as native modules. Its controls: a module is not a classic script, a dynamic import and an oversize bundle are seen, an undeclared script is an unexpected request, a missing global is reported.
- `npm run test:examples` (`scripts/check-examples.mjs`) loads the minified bundles from `dist/` in the five pages of `examples/` and in the two smoke pages of `test/examples-smoke/` (the ESM entry `dist/esm/index.js` and a plugin written against `hic-live-effects.iife.min.js`), in headless Chrome, with a control that breaks the `dist/` path.
- The browser gates (`test/gates/`) load the core, and the effects and water bundles for the effect gates, from `dist/` through `--bundle-file`, `--effects-file` and `--water-file`; the mutant suite mutates the core or the effects file (`bundle: 'effects'`) and runs the gates on it.
